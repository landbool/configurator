### СПЕЦИАЛЬНЫЕ ИНЖЕНЕРНЫЕ ПРАВИЛА КОНФИГУРАТОРА

#### 1. ПРАВИЛО ОТКАЗОУСТОЙЧИВОСТИ СЕТИ И ВНЕШНИХ ЗАГРУЗОК (NETWORK RESILIENCE)
- **Запрет нестабильных API**: Для загрузки SVG-чертежей запрещено использовать `api.github.com/gists/...` из-за лимита 60 запросов/час. **Строго использовать прямые Raw Gist ссылки (`https://gist.githubusercontent.com/.../raw/...`)** либо локальные встроенные схемы.
- **Изоляция сетевых запросов**: Запрещено оборачивать независимые сетевые запросы в единый `Promise.all`. Применять независимую асинхронную загрузку (`Promise.allSettled` или индивидуальные блоки `try { ... } catch`), чтобы сбой загрузки одной серии или таблицы не ломал работу конфигуратора для остальных серий.
- **Отказоустойчивые фолбэки (Fallback Catalog & Drawings)**: Конфигуратор обязан содержать резервный каталог и резервные изображения/схемы, чтобы при отсутствии связи с Google Sheets или Gist интерфейс оставался полностью работоспособным.

#### 2. ПРАВИЛО МАНИПУЛЯЦИЙ SVG И КАЛИБРОВКИ ЧЕРТЕЖЕЙ
- **Неприкосновенность структуры Gist-чертежей и сохранение белых маскирующих прямоугольников:**
  * При получении SVG-чертежа из GitHub Gist **категорически запрещено удалять белые прямоугольники/плашки** (`<rect fill="white">`) или сдвигать любые графические элементы чертежа.
  * Буквенные обозначения параметров уже нанесены пользователем на свои точные места. Задача субагентов — связать буквенные обозначения с таблицей и разместить динамические элементы `<text data-param="...">` строго по центрам соответствующих белых прямоугольников без изменения координат и с сохранением углов поворота (`transform="rotate(...)"`).
  * Все белые маскирующие прямоугольники должны оставаться нетронутыми в итоговом SVG, чтобы надёжно закрывать исходные фоновые надписи без наложений и визуального мусора.
- **100% точное регистрозависимое сопоставление параметров (Exact Case-Sensitive Key Matching):**
  При привязке меток чертежа к базам данных и таблицам подбора строго соблюдать точное совпадение ключей с учетом регистра (1-к-1):
  * Если на чертеже указан параметр `h4`, искать в базе строго `h4` (толщина лапы), а не `h`, не `h1`, не `H4`.
  * Если указан `h`, искать строго `h` (высота оси вала).
  * Если указаны `D2`, `D1`, `D`, `d`, `o2`, `o1`, `a5`, `a`, `b`, `e`, `f`, `n`, `s`, `p3` — каждый параметр связывается строго со своим одноименным столбцом таблицы без сокращений, подмен или группировок.
  * Запрещено применять сопоставление по неполным префиксам или нормализацию регистра `toLowerCase()`.
- **Динамическая параметризация**: Замена размерных меток в SVG осуществляется строго по атрибуту `text[data-param]` с центровкой (`text-anchor="middle"`), пересчетом `bbox` и сохранением матриц трансформации (`transform`).
- **Индивидуальная калибровка серий**: Для каждой серии (`GR`, `GRF`, `GK`, `GF`, `GS`, `GS39`, `GS109`, `GSF109`, `GRX`, `GRXF`) строго поддерживать индивидуальные параметры `viewBox`, коэффициенты масштабирования шрифтов и отступы под длинные значения (например, диаметры валов, допуски, многострочные обозначения).
- **Экспорт в PDF**: Рендеринг SVG на Canvas перед отправкой в `jsPDF` должен выполняться на белом непрозрачном фоне (`#FFFFFF`) с точным соблюдением пропорций `orientation` (альбомная/портретная) и исходного разрешения чертежа.

#### 3. ПРАВИЛО ФОРМИРОВАНИЯ МАРКИРОВКИ И БИЗНЕС-ЛОГИКИ
- Строго соблюдать структуру маркировки Guomao G-серии:
  * Для стандартных двигателей: `[Модель]-[ТипДвигателя][Мощность]-[Полюса]-[Передаточное]-[Положение]-[УголКоробки]-[ВыходКабеля]`.
  * Для исполнения с входящим валом (`AD`): исключать параметры клеммной коробки и стороны выхода кабеля (`[Модель]-AD-[Передаточное]-[Положение]`).
- Блокировать несовместимые комбинации (например, малый фланец B14 для неподдерживаемых габаритов, несовместимые типы валов и моментных рычагов).
- При изменении конфигурации синхронизировать URL через `history.replaceState(..., '?m=...')` для возможности сохранения и шеринга прямой ссылки на выбранный редуктор.

#### 4. ПРАВИЛО ВЕРСТКИ И ДИЗАЙНА UI (TAILWIND CSS / MODALS)
- Верстка интерфейса должна быть полностью адаптивной (мобильные устройства, планшеты, десктопы до 2K/4K).
- Модальные окна (`#drawingModal`, `#requestModal`, `#toast`) должны быть изолированы на верхнем уровне `<body>`, иметь плавные переходы (`opacity`, `backdrop-blur`) и корректно закрываться по клику на оверлей, кнопку закрытия и клавишу `Esc`.
- Защита от ошибок `null / undefined`: все обращения к элементам DOM (`document.getElementById`) и парсинг строк должны содержать проверки на существование (`?.` / `if (el)`).
